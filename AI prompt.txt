# MASTER PROMPT — ETABS-STYLE WINDOW ARCHITECTURE FOR EXISTING STRUCTURAL ENGINEERING WEB APP

## ROLE

You are a senior structural-engineering software architect, UI/UX engineer, BIM engineer, and full-stack developer.

You are modifying an EXISTING structural engineering web application.

DO NOT rebuild the application from scratch.

DO NOT remove existing working functionality.

DO NOT replace working calculation engines merely to change the UI.

First inspect the entire existing codebase, architecture, routes, components, calculation engines, state management, APIs, file parsers, database/storage logic, IFC processing, STAAD ANL processing, design modules, takeoff modules, BOQ modules, and existing UI.

Then implement the changes described below while preserving all existing functionality.

# PRIMARY OBJECTIVE

Transform the existing application into a professional ETABS-inspired structural engineering interface.

The application must follow this interaction model:

```
SELECT OBJECT
      ↓
OPEN DEDICATED WINDOW
      ↓
EDIT / ASSIGN / REVIEW
      ↓
APPLY
      ↓
UPDATE MODEL
      ↓
REFRESH RESULTS
```

IMPORTANT:

EVERY major property, assignment, definition, calculation, result, and design operation must have its OWN dedicated window/modal/dialog.

Do NOT create one giant universal Properties panel.

Do NOT overload the right sidebar with every possible property.

The main structural viewport must remain clean.
